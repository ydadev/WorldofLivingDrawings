# Интерфейс действий подводного мира

Рабочие страницы первой версии находятся в браузерном приложении: `world.html` для владельца на ПК, `viewer.html` для основного экрана/TV и `controller.html` для телефона, планшета или второго ПК. Все используют `WorldInteractionUi`, версионированный пакет `underwater` и `SceneConnection`. Страницы пока собираются в прототипе Vite; развёртывание статических файлов вместе с backend относится к MVP-05.

Владелец входит по логину и паролю, указывает существующую сессию или создаёт новую. Сервер выдаёт HttpOnly cookie и CSRF для текущей страницы; пароль после входа удаляется из поля. Владелец может открыть PIN-приглашение Controller или разрешить запрос Viewer по восьмизначному коду с выбором права `interact`. Viewer запрашивает код на своём экране, владелец подтверждает его; до подтверждения страница ожидает. Read-only Viewer видит сцену без панели действий. Controller вводит ID сессии и шестизначный PIN, затем открывает облегчённый вид мира по запросу. При закрытии или уходе страницы Controller в фон WebGL renderer освобождается, новое открытие загружает snapshot. Отображаемые коды не записываются в журнал или URL.

Последовательность действия: выбор «Корм»/«Подводная лодка» → точка в фиксированном боковом виде → отправка одного `commandId` → индикатор ожидания ACK → ожидание серверного `interaction_state` → показ результата. Нажатие вне воды, перетаскивание, долгое удержание, UI-кнопка и отмена Escape не отправляют команду. Для браузера TV кнопки доступны с клавиатуры: после выбора действия фокус переходит к canvas, стрелки двигают прицел, Enter подтверждает точку. Сервер заново проверяет права, область, квоты и маршрут; понятная причина отказа показана рядом со сценой.

Controller использует тот же Babylon renderer с масштабом кадра 0,5 и создаёт его только при открытии вида. Это функциональный LOW-режим, не доказательство нужной частоты кадров на конкретном телефоне или TV. Главный экран и Controller переводят клик/тап в мировые координаты собственной камеры и отправляют только их. Клиент применяет snapshot, revisioned delta и временные положения; исходы событий определяет сервер.

Проверка `npm run test:live-ui` в `prototypes/wasm-webgl` запускает Chrome и локальный сервер с **тестовой** реализацией того же HTTP/WS-контракта. Она проверяет Owner, read-only и интерактивный Viewer, Controller, код подключения, координаты на разных размерах, жесты, клавиатуру, отказ, повторное открытие и reconnect. Backend отдельно проверяется PostgreSQL-тестами. Совместная проверка страниц с настоящим backend, публикация статических страниц на домене, реальные телефоны/TV и десятиминутная нагрузка ещё не выполнены; их нельзя считать закрытыми по mock-тесту.
