# Каркас и границы модулей

Дата: 2026-09-29. Контракты CORE-01 расширены серверным каркасом и транспортом CORE-03; продуктовый Viewer и симуляция ещё не готовы.

## Направления зависимостей

| Модуль | Владеет | Может зависеть от |
|---|---|---|
| `web/contracts` и `schemas/v1` | Структура данных, явные версии | Ни от UI, ни от Babylon |
| `web/renderer` | Интерфейс отображения snapshot/delta и указания точки | Только контракты |
| `web/renderer-babylon` | WebGL 2, фиксированная камера и GPU-объекты | Renderer interface, контракты, Babylon |
| `web/transport` | WSS, порядок snapshot/delta, reconnect и выяснение исхода команд | Только контракты и браузерный WebSocket |
| Capture и Editor | Два способа создания `PaintResult` | PaintLayout и контракты, не Simulation |
| `crates/ldw-server` | Права, epoch/revision, подтверждение/журнал команд | Контракты и PostgreSQL; не браузер/renderer |
| `crates/ldw-sim` | Чистое детерминированное движение, далее реакции и ресурсы | Геометрия/параметры из версионированного контента |
| `content/underwater` | Декларативные определения и ассеты | Только версионированная схема; без исполняемого кода |

Корневой `package.json` описывает четыре TypeScript workspace. Папка `prototypes/` остаётся самостоятельным стендом этапа 0. `crates/ldw-server` — серверный каркас; продуктовые Viewer/Controller и симулятор остаются следующими задачами. Проверочный `interaction-server.mjs` не превращается в production backend.

## Контракты и версии

`schemas/v1/definitions.schema.json` задаёт `WorldDefinition`, `EntityDefinition`, `InteractionDefinition`, `PaintResult`, `SceneSnapshot`, `SceneDelta` и `AssetManifest`. `web/contracts` содержит соответствующие TypeScript-типы, включая поля транспорта snapshot/delta. `schemaVersion: 1` обязателен, дополнительные поля запрещены; неизвестная версия отклоняется. Новая несовместимая форма получает `v2` и явную миграцию, без тихого изменения v1. Версии мира, определения и шаблона независимы; существующая сцена хранит свои ссылки, а новое содержимое не перекрашивает старые объекты автоматически.

`PaintResult` ссылается на проверенный перекодированный PNG через `blobId`; сырая фотография и `data:` URL в контракт не входят. `sourceKind` сообщает происхождение (`paper`/`browser`), но не меняет права, симуляцию или Renderer. `layoutHash` связывает рисунок с конкретной геометрией/маской шаблона. Оба пути раскраски должны нормализовать изображение до передачи серверу; сервер позже проверит действительную связь blob, layout и размера.

Мировые координаты в боковой плоскости: +X вправо, +Y вверх, Z=0 для выбора точки. Фиксированный ViewProfile подводного пакета — 16×9 единиц; допустимая зона `water` задана в пакете. Камера не переключается. `SceneSnapshot` задаёт epoch/revision и полный набор сущностей; `SceneDelta` принимается renderer только при той же epoch и следующей ревизии. При разрыве `web/transport` создаёт новое WebSocket-соединение и запрашивает свежий snapshot; неизвестный исход команды сначала выясняет по прежнему `commandId`. Проверочный адаптер рисует нейтральные маркеры сущностей; GLB, анимации и 100 рыб относятся к CORE-04.

`InteractionIntent` передаёт только вид действия и мировую точку с `commandId`/epoch; состав участников и исход не задаются клиентом. Проверка полномочий и идемпотентность принадлежат серверу.

## Ассеты и проверка

`content/underwater` содержит мир, два определения рыб, два действия и восемь файлов ассетов. `tools/build-content.mjs` формирует локальную копию GLB, PaintLayout и шаблонов из проверенного генератора этапа 0 и создаёт `manifest.json`. Все пути относительны пакету; SHA-256 каждого файла, отсутствие выхода из пакета, ссылки между миром/сущностями/действиями, версии шаблонов и строгая JSON Schema проверяются `npm run test:contracts`. GLB уже дополнительно проверяет `verify-fish.mjs` на самодостаточность и Paint UV. Поля лицензии в этом тестовом пакете отмечают внутреннее проектное содержимое; публикация стороннего пакета потребует доказанных прав и расширенной проверки карантина.

`npm ci`, `npm run build:content`, `npm run test:contracts`, `npm run typecheck`, `npm run test:transport` проверяют корневой workspace. `prototypes/wasm-webgl` после собственной сборки выполняет `npm run test:core-renderer`: Chrome проверяет WebGL 2, одинаковую мировую точку при разных размерах экрана, порядок snapshot/delta и отказ на несовместимую версию. Сервер проверяется отдельно в Ubuntu/PostgreSQL CI. Production deployment, реальная точность фото и TV остаются незакрытыми воротами приёмки.
