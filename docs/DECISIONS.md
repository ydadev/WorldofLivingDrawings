# Реестр решений

| ID | Статус | Решение | Основание / последствия |
|---|---|---|---|
| ADR-001 | ACCEPTED | Первый релиз — один подводный мир | Город/ферма и полные редакторы контента отложены |
| ADR-002 | ACCEPTED | Одна фиксированная камера на мир | Подводный мир выглядит как аквариум сбоку; переключения ракурсов нет |
| ADR-003 | ACCEPTED | Одна раскраска на обе стороны объёмной рыбы | Подготовленные Paint UV, без второго снимка |
| ADR-004 | ACCEPTED | Бумажная и браузерная раскраски входят в MVP | Один PaintResult; редактор в Controller телефона/планшета/ПК |
| ADR-005 | ACCEPTED | Исходы событий определяет сервер | Клиенты предсказывают/интерполируют; нет требования float lockstep |
| ADR-006 | ACCEPTED | Управление на экране мира и Controller | Выбор в координатах мира; одинаковая сцена на разных устройствах |
| ADR-007 | ACCEPTED | Rust + TypeScript + Babylon Adapter + PostgreSQL | Контракты не зависят от UI/renderer; WASM/WebGL 2 базовый профиль |
| ADR-008 | ACCEPTED | NPM отдельно управляет HTTPS | Публичный домен → NPM → HTTP:80 приложения; Caddy/Certbot на приложении не нужны |
| ADR-009 | ACCEPTED | Сервер runtime — Ubuntu 24.04 + Docker Compose | Тяжёлые сборки/authoring отделены от рабочего runtime; версии образов фиксируются |
| ADR-010 | ACCEPTED | Публичная Git-identity только ydadev, сообщение только дата | GitHub noreply, локальные hooks и CI; пояснения находятся в WORKLOG |
| ADR-011 | ACCEPTED | Сервер сохраняет рисунки до явного удаления | Квоты блокируют новые операции; корзина 7 суток; детали в operating-rules |
| ADR-012 | ACCEPTED | Цифровые черновики сохраняются локально по выбору | Не занимают слот в мире; сервер хранит результат после «Оживить» |
| ADR-013 | ACCEPTED | На этапе подготовки backup хранится в `.local/backups/` проекта и исключён из GitHub | Прямое решение пользователя; автоматическое внешнее хранилище добавляется позже до рабочего запуска |
| ADR-014 | ACCEPTED | Технический результат бумажного Capture отделён от количественной приёмки на физических фото | RISK-03-TECH уже подтверждён синтетикой и CI и допускает CORE-01; RISK-03 остаётся BLOCKED, обязателен для MVP-01 и не может быть объявлен PASS без реальных снимков |
| ADR-015 | ACCEPTED | Новые рыбы в работающей сцене проходят через долговечную очередь, которую применяет единственный runner сцены | При записи Entity напрямую в БД живая модель runner могла бы разойтись с checkpoint. Runner на логической границе одной транзакцией публикует Entity, checkpoint и события; очередь удаляется только при commit. Внутренний вызов принимает лишь заранее проверенный PaintResult; публичный upload и доступ реализуются в MVP-01/02 |
| ADR-016 | ACCEPTED | Подтверждённое кормление сначала хранится как намерение, затем единственный runner применяет его вместе с checkpoint и событием состояния | ACK означает устойчивую принятую команду, а не уже созданный источник. `pendingInteractions` очищается только при commit состояния ядра; изменение порций/истечение также фиксируются с ревизией. Пустая сцена получает исходный checkpoint, чтобы источник мог истечь без рыб. Права, лимит источников и cooldown участника/сцены проверяются до ACK под блокировкой сцены. Это сохраняет подтверждённые исходы после restart; клиент должен показывать фазу ожидания до `interaction_state` |

Для нового существенного решения добавить ID, контекст, рассмотренный выбор, принятое поведение и затронутые задачи. Отмена помечается SUPERSEDED со ссылкой на новое решение; история не удаляется.
